# 引导与追问回执

Android 聊天页与桌面的智能工作台、AI 面板支持在任务运行时发送引导或追问，并查看发送回执。引导在下一次安全边界进入当前轮的模型上下文；追问在当前任务成功后创建新的任务和执行轮次。

## 查看与重试

发送时生成并保存稳定的消息标识。网络中断后，界面会保留“结果待确认”的原始请求；刷新回执只查询，不自动重新发送。点击重试仍使用原标识和原正文。发送后继续编辑的新草稿不会被迟到的确认清空。账号、服务器、项目、会话或任务切换后，旧请求不能修改新页面的状态。

服务器可能对正文脱敏，因此查询结果与原正文不同不等于发送冲突。客户端保留未确认请求，手动重试由服务器检查原始正文摘要；成功响应确认送达，明确的 409 响应表示拒绝。服务端原文摘要不通过接口公开。未确认请求会保存在当前设备的账号范围内，以支持关闭再打开后的查询和手动重试。

| 显示状态 | 能确认的事实 |
| --- | --- |
| 发送中／结果待确认 | 当前设备尚未取得可靠确认 |
| 已接收，等待处理 | 服务器已保存消息，尚未进入上下文或创建后续任务 |
| 已加入本轮上下文 | 引导已写入当前轮的规范用户消息；不证明模型遵从或完成要求 |
| 后续任务已创建 | 服务器已持久化具体任务和轮次；可点击查看其执行状态 |
| 本轮结束前未加入上下文 | 引导没有赶上本轮的安全边界 |
| 后续任务未创建 | 父任务或前序追问失败、取消、中断，或旧记录缺少必要关联 |
| 回执状态未知 | 旧协议、缺失证据或矛盾字段不能支持可靠判断 |

追问按同一个源任务上的接收顺序执行：前一条追问创建的任务成功后，才创建下一条。不同源任务的历史失败不会阻塞新的队列；项目原有的工作区执行锁仍然生效。暂停时继续等待，失败、取消或服务中断时不自动启动剩余追问。已经创建的任务关联不会因为后续状态变化而消失。

## 接口与持久化

`POST /api/jobs/{job_id}/messages` 接收 `message_key`、`type` 和 `payload`。首次接收返回 201，相同标识与原始正文的重试返回 200，包括任务结束后的重试。相同标识配不同类型或正文、或者向已经结束的任务发送新标识，返回 409。账号所有权检查、已有请求识别和新请求入库在同一事务中完成。访客仍无此接口权限。

`GET /api/jobs/{job_id}/messages?include_consumed=true` 返回待处理与已处理消息，按消息 ID 排序。省略该参数时只返回未消费记录。接口还可能包含取消、暂停等控制消息，客户端的用户消息列表只显示引导与追问。

响应信封包含 `schema_version: 1`、`job_id` 与 `message` 或 `messages`。每条消息包含：

- `id`、`task_id`、`message_key`、`type`、`payload`、`created_at`、`consumed_at`。
- `delivery_state` 与可选 `reason`。
- 已进入上下文的引导具有 `context_message_id`。
- 已创建任务的追问具有 `follow_up_job_id` 和 `follow_up_turn_id`。

追问子任务、执行轮次、规范用户消息、永久关联和消费时间在同一 SQLite 事务中创建。周期调度会重新发现成功父任务的未处理追问，以覆盖完成回调前后的重启窗口。并发调度复用同一个关联。引导按规范消息身份去重；相同文字使用新标识发送时仍保留为两条独立输入。

如果模型服务故障并切换到已配置的备用服务，会从最新的规范历史重建上下文和响应计数，保留已经消费的引导及完成的工具结果。不会继续使用初始历史快照而丢掉已确认的消息。

旧版已消费但没有关联证据的记录保持未知，不猜测子任务。客户端查看后续任务前会再次查询并核对项目、会话、任务和执行轮次。查看动作不会自动恢复或继续执行。

## 验证范围

后端单元测试覆盖事务回滚、多进程并发、账号隔离、脱敏后的原始正文幂等和 FIFO 调度。HTTP/WebSocket E2E 场景 30–34 覆盖丢响应后的原标识重试、同文独立引导、实际副作用计数、追问顺序、父任务取消、失败与真实服务崩溃重启。客户端另有解析、草稿保护、重开对账和迟到响应测试，并通过 Chromium、Electron 与 Android 模拟器检查实际交互。

这些测试使用隔离账号、临时数据和本地模型桩，不调用付费模型。每轮发布门禁结果与设备证据记录在 [迭代记录](ITERATION_LOG.md)。队列编辑、服务端删除和重排尚未开放。
