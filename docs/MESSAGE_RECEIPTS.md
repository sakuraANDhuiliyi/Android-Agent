# 引导与追问回执

Android 聊天页与桌面的智能工作台、AI 面板支持在任务运行时发送引导或追问，并查看发送回执。引导在下一次安全边界进入当前轮的模型上下文；追问在当前任务成功后创建新的任务和执行轮次。

## 查看与重试

发送时生成并保存稳定的消息标识。网络中断后，界面会保留“结果待确认”的原始请求；刷新回执只查询，不自动重新发送。点击重试仍使用原标识和原正文。发送后继续编辑的新草稿不会被迟到的确认清空。账号、服务器、项目、会话或任务切换后，旧请求不能修改新页面的状态。

服务器可能对正文脱敏，因此查询结果与原正文不同不等于发送冲突。客户端保留未确认请求，手动重试由服务器检查原始正文摘要；成功响应确认送达，明确的 409 响应表示拒绝。服务端原文摘要不通过接口公开。未确认请求会保存在当前设备的账号范围内，以支持关闭再打开后的查询和手动重试。

| 显示状态 | 能确认的事实 |
| --- | --- |
| 发送中／结果待确认 | 当前设备尚未取得可靠确认 |
| 已接收，等待处理 | 服务器已保存消息，尚未进入上下文或创建后续任务 |
| 已加入本轮上下文 | 引导已写入当前轮的规范用户消息；不证明模型遵从或完成要求 |
| 后续任务已创建 | 服务器已持久化具体任务和轮次；可点击查看其执行状态 |
| 本轮结束前未加入上下文 | 引导没有赶上本轮的安全边界 |
| 后续任务未创建 | 父任务或前序追问失败、取消、中断，或旧记录缺少必要关联 |
| 追问已撤回 | 服务器已持久化撤回，该消息不会再创建后续任务 |
| 回执状态未知 | 旧协议、缺失证据或矛盾字段不能支持可靠判断 |

追问按同一个源任务上的接收顺序执行：前一条追问创建的任务成功后，才创建下一条。不同源任务的历史失败不会阻塞新的队列；项目原有的工作区执行锁仍然生效。暂停时继续等待，失败、取消或服务中断时不自动启动剩余追问。已经创建的任务关联不会因为后续状态变化而消失。

## 撤回追问

当回执确认追问尚未消费、尚未创建子任务时，点击“撤回追问”可收回该条指令。父任务已经失败、停止或暂停时，符合条件的追问仍可撤回。撤回保留原消息和审计记录，其他追问的顺序保持不变；撤回第一条不会阻塞后面的有效追问。

服务端把撤回和创建子任务放在同一个事务边界上判定。撤回先成功，调度器就不会创建任务；子任务先创建，撤回会被拒绝，并显示其最新回执。撤回不会隐式停止、暂停或恢复已经创建的任务，仍需进入任务页操作。

“移除本地记录”只移除本机未确认发送的记录，不能撤回已送达服务器的消息。撤回丢失响应时显示待确认，可手动“核对并重试撤回”；重开或自动刷新只查询。原发送请求即使再次使用相同标识重试，也只会返回已撤回回执，不会重新排队。旧服务器缺少撤回能力字段时不显示操作入口。

## 编辑排队追问

尚未创建后续任务的可执行追问可以修改正文，保留原消息身份、接收时间与队列位置。编辑窗口与主输入草稿分开；保存只更新这一条追问，不向父任务当前上下文追加引导，也不改变模型、权限或执行模式。失败、停止、中断或损坏关联造成的阻塞队列不可编辑，符合撤回条件时仍可撤回。

每次保存携带打开编辑时的版本。另一个客户端先保存，或者调度器先创建任务时，保存会被拒绝并保留编辑正文；客户端不会自动覆盖较新的版本、重发成另一条追问或控制已创建的任务。用户可查看当前回执后重新决定如何处理。

编辑响应丢失时，当前设备保存该次操作的原标识、原正文及预期版本。重开和刷新只查询；查询显示的最新正文不等于确认本机这次保存成功。人工重试沿用原请求，由服务器返回对应的编辑操作回执。即使后来出现更新版本、追问被撤回或任务已经创建，已接受编辑仍可确认，当前正文及执行状态保持最新结果。

## 接口与持久化

`POST /api/jobs/{job_id}/messages` 接收 `message_key`、`type` 和 `payload`。首次接收返回 201，相同标识与原始正文的重试返回 200，包括任务结束后的重试。相同标识配不同类型或正文、或者向已经结束的任务发送新标识，返回 409。账号所有权检查、已有请求识别和新请求入库在同一事务中完成。访客仍无此接口权限。

`GET /api/jobs/{job_id}/messages?include_consumed=true` 返回待处理与已处理消息，按消息 ID 排序。省略该参数时只返回未消费记录。接口还可能包含取消、暂停等控制消息，客户端的用户消息列表只显示引导与追问。

响应信封包含 `schema_version: 1`、`job_id` 与 `message` 或 `messages`。每条消息包含：

- `id`、`task_id`、`message_key`、`type`、`payload`、`created_at`、`consumed_at`。
- `delivery_state` 与可选 `reason`。
- 已进入上下文的引导具有 `context_message_id`。
- 已创建任务的追问具有 `follow_up_job_id` 和 `follow_up_turn_id`。
- `can_withdraw` 是服务器确认的当前操作资格，只有布尔值 `true` 才允许发起撤回；缺字段默认不允许。
- 已撤回追问的 `delivery_state` 为 `withdrawn`，具有 `withdrawn_at`，没有消费时间、上下文消息或子任务关联。
- `revision` 是正文版本，原始消息为 0；`edited_at` 是最新修订时间，未编辑时为空。`payload` 展示当前版本的脱敏正文。
- `can_edit` 是新编辑的当前资格，缺字段或非布尔真值时不允许发起新编辑；这不影响人工重试已经发出的未确认编辑请求。

`POST /api/jobs/{job_id}/messages/{message_id}/withdraw` 不需要请求正文，首次与重复调用均返回 200 和同一条持久回执。已创建子任务、已消费的旧记录或不支持的消息类型返回 409；不存在或不属于当前账号与任务的消息返回 404，访客返回 403。返回 409 后客户端重新查询消息列表，不从错误文字推断子任务身份。撤回记录存于独立的 `task_message_withdrawals` 表，重复调用保持原时间戳。

`POST /api/jobs/{job_id}/messages/{message_id}/edits` 接收独立的 `edit_key`、非负整数 `expected_revision` 和仅含非空 `text` 的 `payload`。首次保存返回 201，原请求重试返回 200；同编辑标识配不同请求、过期版本或新操作不再符合资格返回 409。响应同时包含不可变的 `edit` 操作回执和当前 `message`：前者包含任务与消息身份、编辑标识、预期及接受版本、时间和该次正文；后者可能已经处于更高版本或执行终态，两者不能相互覆盖。

`task_message_revisions` 追加保存修订，原始 `task_messages` 正文与发送请求摘要保持不变，原发送重试仍按原请求判定。版本校验、修订写入、撤回与子任务创建使用同一数据库写事务。子任务创建时读取最新正文，并在规范用户事件中记录 `task_message_revision`。编辑过的消息只允许与最新版本相符的子任务关联入库，旧 worker 未携带版本时整个创建事务回滚；发布时仍需更新并重启所有 API 和 worker 进程。导出与恢复包含修订、关联和撤回记录。

追问子任务、执行轮次、规范用户消息、永久关联和消费时间在同一 SQLite 事务中创建。周期调度会重新发现成功父任务的未处理追问，以覆盖完成回调前后的重启窗口。并发调度复用同一个关联。引导按规范消息身份去重；相同文字使用新标识发送时仍保留为两条独立输入。

如果模型服务故障并切换到已配置的备用服务，会从最新的规范历史重建上下文和响应计数，保留已经消费的引导及完成的工具结果。不会继续使用初始历史快照而丢掉已确认的消息。

旧版已消费但没有关联证据的记录保持未知，不猜测子任务。客户端查看后续任务前会再次查询并核对项目、会话、任务和执行轮次。查看动作不会自动恢复或继续执行。

## 验证范围

后端单元测试覆盖事务回滚、多进程并发、账号隔离、脱敏后的原始正文幂等和 FIFO 调度。HTTP/WebSocket E2E 场景 30–34 覆盖丢响应后的原标识重试、同文独立引导、实际副作用计数、追问顺序、父任务取消、失败与真实服务崩溃重启；场景 35–39 覆盖队首、中间和末尾撤回、重启与旧请求不复活、子任务先创建时保持审批不变，以及停止父任务后的追问清理；场景 40–45 用真实工具记录模型实际收到的指令，检查队首、中间和末尾编辑保持顺序、仅执行最新正文、服务重启、旧编辑确认、已创建任务的审批不变，以及撤回和停止后不复活。客户端另有解析、草稿保护、重开对账和迟到响应测试，并通过 Chromium、Electron 与 Android 模拟器检查实际交互。

这些测试使用隔离账号、临时数据和本地模型桩，不调用付费模型。每轮发布门禁结果与设备证据记录在 [迭代记录](ITERATION_LOG.md)。队列重排尚未开放。
