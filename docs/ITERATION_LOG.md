## 引导与追问回执

日期：2026-10-10。状态：实现、交叉审查和完整验收完成。以上一轮已推送的 `e827f86` 为基线。

本轮目标是让发送后的引导与追问可追踪、可对账、可安全重试。区分服务器保存消息、消息加入本轮上下文和后续任务创建，不将前两者描述成模型已采纳或工作已完成。首次发送生成稳定消息身份，丢失响应后的重试沿用相同身份与正文；两个有意发送的同文消息仍各自保留。

调研依据：[Codex 手机工作流](https://developers.openai.com/blog/mastering-codex-remote-for-engineering#2-learn-the-difference-between-queue-and-steer) 区分本轮引导和下一轮队列；[Cursor Agent](https://cursor.com/docs/agent/overview#queued-messages) 展示消息顺序并在工具边界接收引导；[Claude Code 交互说明](https://code.claude.com/docs/en/interactive-mode#queue-messages-while-claude-works) 显示尚未处理的输入，部分消息可在同轮工具完成后进入上下文。各平台的队列语义不同，本项目继续区分 `steer` 与 `follow_up`，借鉴可见回执和安全边界。

已确认的当前缺口：`include_consumed=true` 仍只返回待处理消息，响应缺少消费与后续任务身份；终态检查早于幂等查询，成功但丢失响应的请求可能在重试时被拒绝；追问创建与消费分别写入，重启或并发可能丢失调度或重复创建。双端还缺少稳定重试、迟到响应与新草稿的完整隔离，Android 任务运行时缺少可见的触摸发送入口。访客目前没有此接口权限，本轮保持 403，不扩大额度及授权范围。

采用保守的自动追问策略：父任务成功后按顺序创建后续任务；普通失败、取消或服务中断时保留可见阻塞回执，不自动执行。已经创建的后续任务关联永久保留。队列编辑、删除和重排不属于本轮。使用与协议见 [引导与追问回执](MESSAGE_RECEIPTS.md)。

交叉审查发现首个模型服务消费引导后发生故障时，备用服务会沿用旧历史快照，遗漏已确认消息。现切换前重读规范历史，同时恢复上下文与响应计数；新增双向 OpenAI/Anthropic、首次请求故障及完成工具后故障的四种回归，检查同文独立引导、原始提示和实际文件副作用均不丢失或重复。刷新范围限于初始历史和当前轮，运行期间后来排队的下一轮输入不会混入。发现此边界时终止了初次发布检查，保留日志并在定版后完整重跑。

最终默认发布门禁 **24/24 全通过，无跳过项**，报告 `.artifacts/iteration-004/release.json`：后端 **644 项测试、68 项子测试**；完整 HTTP/WebSocket E2E **34/34**；Android **229 项 JVM 测试**、Debug 构建和 lint（0 错误、347 条警告）；桌面单元、Chromium 双入口回执与旧功能回归、真实 Electron 消息/恢复/验证及原有 smoke、截图、创意接口全部通过，npm audit 为 0 漏洞。共享 API 回执样例由两端实际解析测试覆盖，Android 资源副本与契约校验值一致。

Android 模拟器另完成 **14 项设备验收**，覆盖发送与停止、回执状态、查看暂停子任务但不自动继续、脱敏失响应后重开并使用原标识重试、后台停止查询、返回刷新及迟到确认保护新草稿；报告 `.artifacts/iteration-004/android-results.json`。设备脚本核验预期检查集完整才报告通过，合成账号配置、数据库、服务和端口映射已清理。既有历史翻页测试的 Main 线程竞态也已修正，保留原断言和超时条件。两处桌面回执截图已目视验收，证据保存于同一忽略目录。

## 撤回尚未执行的追问

日期：2026-10-10。状态：实现、交叉审查和完整验收完成。以上一轮已推送的 `f1d7218` 为基线。

本轮只增加单条追问撤回。目标是在服务器尚未创建后续任务时收回指令，并让重开、断网和重试都保持这一结果。保留消息及其原始幂等身份，使用独立的持久撤回记录；撤回与子任务创建竞争同一个数据库写事务。任务已经创建时拒绝撤回，仍通过已有任务页进行显式控制。编辑、排序和强制执行不在本轮范围。

调研核实：[Codex 提示词说明](https://learn.chatgpt.com/docs/prompting#steering-and-queuing) 明确区分当前执行引导和下一轮队列，并提供编辑、排序、发送和删除；[Claude Code 交互模式](https://code.claude.com/docs/en/interactive-mode#take-back-what-you-queued) 允许将尚未发送的条目取回输入框后编辑或丢弃；[Cursor Agent 队列](https://cursor.com/docs/agent/overview#queued-messages) 展示顺序并支持调整次序。这些公开说明没有给出服务端撤回与任务创建的事务协议；原子竞争、永久回执和不隐式取消任务是本项目的实现选择。

验收覆盖队首、中间和末尾撤回后的实际执行顺序；原发送标识重试不得复活；重复撤回、失响应、服务重启与多进程竞争；已创建子任务保持状态与审批不变；失败或停止父任务的未执行追问仍可清理；双端旧回执、迟到响应、账号隔离、重开查询与草稿保护。补齐 SQL 导出遗漏的后续任务关联及撤回表，实际恢复后验证原身份与撤回状态继续有效。

## 保留队列位置的追问编辑

日期：2026-10-10。状态：实现、交叉审查和完整验收完成。以上一轮已推送的 `5d83b0c` 为基线。

本轮增加追问正文编辑，保留原消息身份、接收时间和 FIFO 位置。原始发送正文与请求摘要不变，每次编辑以独立操作标识和预期版本追加修订；只有尚未执行且未阻塞的追问可以发起新编辑。编辑、撤回和调度竞争同一个数据库事务，任务已经创建时保留原任务与审批。

调研依据：[Codex 队列](https://learn.chatgpt.com/docs/prompting#steering-and-queuing) 支持编辑排队消息；[Cursor 2.3](https://cursor.com/changelog/2-3) 介绍编辑与调整队序；[Claude Code 取回队列](https://code.claude.com/docs/en/interactive-mode#take-back-what-you-queued) 则将消息取回输入框，编辑后重新排队。本项目选择保留原队位的修订模型：简单撤回再重发会改变队位，并在父任务终态后受到新消息限制。公开资料未说明各产品内部事务实现，本轮版本与幂等协议属于本项目设计。

每次编辑响应包含不可变的操作确认及当前消息快照。已接受请求即使后来出现更新版本、撤回或创建任务，仍可用原标识核对；客户端不能把旧确认中的历史正文覆盖到较新快照。重开与自动刷新仅查询，查询结果不证明本机保存操作已被接受；人工重试保留原标识、正文和版本。编辑草稿与主输入隔离，版本冲突不会自动重发为另一条消息或本轮引导。

官方资料已复核：[Codex App Server](https://learn.chatgpt.com/docs/app-server) 区分 turn 生命周期与完成事件；[Claude Code 交互模式](https://code.claude.com/docs/en/interactive-mode) 明确中断与权限提示的行为；[Cursor Agent](https://cursor.com/help/ai-features/agent) 描述停止与检查点交互；[OpenAI Agents SDK 人工审批](https://developers.openai.com/api/docs/guides/agents/guardrails-approvals) 提供恢复审批状态的架构参考。[Cursor 社区反馈](https://forum.cursor.com/t/make-agent-chat-tab-visually-obvious-when-waiting-for-run-approval/156250) 反映等待审批状态可见性问题。公开资料没有说明这些产品如何安全实现可重复的服务端暂停、取消与 worker 最终化并发。

本轮已隔离复现：同一任务第二次、第三次暂停虽设置持久标志，固定 `pause:{task_id}` 消息已消费且不能重插，worker 只检查消息，因此无法再次暂停。计划一次解决“可重复暂停与准确控制状态”：pause 资格在 writer 事务中校验；等待审批时稳定返回 409 且不改审批/暂停状态；DTO 明确 `pause_requested`、`can_pause` 及受限原因码；取消与暂停竞争由事务决定，规范 turn 终态仅写一次；兼容旧消息入口且不复活已消费消息。桌面 AI/CX/inbox 与 Android 显示请求中、已受理、待审批和真实暂停的区别，旧/矛盾能力不授予新暂停操作，Stop 可抢占。未决审批持久挂起、continuation 与敏感参数恢复延期。

验收标准：同一任务至少三轮 pause/resume 且每轮仅执行一次工具；queued/running/awaiting 审批边界、先暂停后停止和先停止后 worker park、worker/API 双向迟到最终化、旧 pause 消息重放及冲突、服务重启、消息 API、审批无隐式决定；双端严格解析共享真实 HTTP 回执，覆盖 Stop 抢占、晚响应、A→B→A、列表/watcher 迟到和草稿保留；Chromium 双入口、真实 Electron、Android JVM 与冻结 APK 设备完整集及默认发布门禁全部通过后方可推送。

最终默认发布门禁 **26/26 全通过，无跳过项**，报告 `.artifacts/iteration-010/release-final.json`。后端 **732 项测试、292 项子测试**；真实 HTTP/WebSocket **62/62**；Android **310 项 JVM 测试**、Debug 构建及 lint（0 错误、358 条既有警告）；桌面代码检查、单元、Chromium 双入口、截图、Electron 原 smoke、场景、恢复、交付、消息与提交场景全通过，npm audit 为 0 漏洞。Android 模拟器最终 APK 设备验收覆盖运行中暂停标志、等待审批提示、审批期间不提供新暂停入口、Stop 保留及无写请求，共 **5/5**，73 条请求均为 GET；合成账号、缓存数据库、偏好设置和 adb reverse 已清理，原模拟器用户文件清单恢复不变。关键画面保存于 `.artifacts/iteration-010/device/`。首次完整运行曾暴露样例布尔类型/能力字段、桌面测试夹具和 API 契约锁未同步问题；保留失败报告，修正所有夹具与测试后，以最终冻结源码重新运行全部门禁并通过。
