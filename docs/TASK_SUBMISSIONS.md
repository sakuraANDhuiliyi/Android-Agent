# 任务提交确认

本轮接入正式账号在已确认会话中发起任务的确认与重试流程。Android 主聊天页、桌面 AI 面板和智能工作台在发送前保存完整请求；响应丢失后保留原请求，避免再次点击发送时无意创建另一个任务。

## 使用方式

发送中的正文、上下文附件、模型和执行模式以点击时的内容为准。请求保存成功后才发送；本机无法保存时不发起任务。发送期间仍可编辑下一份草稿，迟到的响应不能清掉新输入或把页面切回旧任务。

关闭页面、重新登录同一账号或网络恢复后，只查询原提交，不自动重发。查询显示“已找到关联任务，原提交待确认”时，仅表示服务器找到了该标识；点击人工确认／重试，才会用原正文和原标识核对。后来修改模型、附件或执行模式不会改变这次重试的内容。任务即使已经完成、暂停或取消，确认也只返回原任务，不继续执行它。

待确认期间可以继续查看会话历史，已连接任务的停止按钮保持可用。客户端不会通过缓存或“最新任务”自动连接这个未确认任务，避免查询时触发订阅或审批。切换账号、会话、任务或进入后台后，旧响应不能修改当前页面。

“仅移除本机记录”需要明确确认。它删除当前设备保存的请求，不取消可能已经创建的服务器任务；以后重新发送属于一次新提交，可能重复原工作。移除保持当前草稿和已有连接，且会让该会话保持手动选择任务，重开也不会自动连接最新任务。新的有效提交确认可连接其确切任务并恢复正常连接行为。

## 范围与容量

当前保证适用于正式账号的 `POST /api/conversations/{conversation_id}/ask`，并要求会话 ID 已经确认。创建会话本身尚无网络幂等保证：创建响应丢失时不会继续提交任务，但服务器可能留下一个空会话。

Android 的主聊天提交接入新流程；首页快速发起、创意“应用到项目”和 Feedback 快捷入口仍使用旧提交流程。项目级 `/api/projects/{id}/ask`、其他未携带请求标识的旧调用和游客提问不在新保证内。客户端不得在新协议被拒绝后自动改用旧协议发送。

本机请求按服务地址、账号、项目和会话隔离，不使用登录 token 作为持久化身份。同一会话最多一个待确认请求，总共最多 10 个，序列化数据最多 2 MiB；保存完整原请求和标识，不保存登录凭据。退出登录不删除待确认请求，重新登录同一账号后可核对。存储损坏或读取失败时停止新提交和自动连接，不将异常当作空记录。手动连接标记不占待确认请求数量，但仍受总存储大小限制。

## 接口

会话提问请求增加可选的 `request_key`。省略或为 null 时保持旧行为；非空时仅允许匹配 `[A-Za-z0-9][A-Za-z0-9_-]{0,199}`，区分大小写、不去除空白。客户端使用独立 UUID。

| 情况 | HTTP 结果 |
| --- | --- |
| 新标识首次接收 | 201，新任务和不可变提交确认 |
| 同账号、同标识、相同完整请求 | 200，原任务和原确认，包括任务终态后的重试 |
| 同标识对应不同正文、选项、附件或会话 | 409，不新建任务 |
| 不存在或其他账号的会话／查询目标 | 404 |
| 游客使用带标识提交或提交查询 | 403，不预扣游客额度 |
| 标识格式错误 | 422 |

带标识的成功响应保持 `job`、`conversation_id`、`guest_remaining`，增加 `schema_version: 1` 和 `submission`：

```json
{
  "schema_version": 1,
  "request_key": "client-generated-uuid",
  "project_id": "project-id",
  "conversation_id": "conversation-id",
  "job_id": "job-id",
  "turn_id": "turn-id",
  "created_at": 1791576000.0
}
```

`GET /api/conversations/{conversation_id}/submissions/{request_key}` 返回 `schema_version`、`submission` 和当前 `job`。它仅查询，不创建任务、启动 worker、审批、继续或恢复。客户端须核对完整归属和任务／轮次身份；确认或当前任务缺失、格式错误或归属不一致时，保留待确认请求，不能部分采用响应。

GET 不证明本机原正文已被接收。服务端保存私有原请求摘要，人工 POST 重试由服务器核对；摘要不通过接口公开。提示正文保持原字串，上下文顺序和所有字段参与身份比较；省略字段等同于显式解析默认值。模型 provider 的 null、空字符串和 `auto` 分别保留，原始敏感值在脱敏前参与摘要，因此两个脱敏后相同的不同原请求仍冲突。

## 持久化与恢复

`task_submissions` 以账号与请求标识唯一关联任务、轮次和接收时间，禁止更新。任务、轮次、首条规范用户事件、提交确认及条件标题更新在同一个数据库事务中提交，提交前 worker 无法看到不完整任务。提交后才启动 worker；启动异常不会撤销已经接收的任务，原请求仍能确认该任务。

确认查询在同一数据库快照核对关联。已经接收的请求先核对原身份，再考虑新任务的额度或模型配置；后续配置变化不能使旧请求创建新任务。损坏的已有关联拒绝使用，不能当作新标识重建。

关联删除使用数据库约束保护；整账号清理显式移除其提交记录。当前删除项目工作区不删除历史确认，历史确认仍可查询；新任务需要项目工作区存在。SQL 导出与恢复包括提交记录。语义 checkpoint 维护和旧入口创建默认／新会话仍位于这个原子提交边界之外。

验收记录见 [迭代记录](ITERATION_LOG.md)。任务运行期间的引导、追问及其编辑、撤回、重排使用独立的[消息回执](MESSAGE_RECEIPTS.md)流程。
