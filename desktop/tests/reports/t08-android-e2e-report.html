三、缺陷与观察

缺陷 #1（P1 · PRODUCT）：特定窗口暂停导致任务失败而非暂停

agent/loop.py · 复现于 pause-grid 时序压测（grid0.45/0.55/0.65）
在模型流式输出进行中请求暂停，PauseRequested 异常被包装为通用 RuntimeError 上抛，任务终态被映射为 failed（“任务失败: 任务已暂停”），而正确语义应为 paused。时序敏感：仅在暂停请求落入特定时间窗时触发（压测中 0.45s/0.55s/0.65s 三个点位复现，0.7s 及以上正常）。

缺陷 #2（P1 · PRODUCT）：暂停态任务无法取消，形成死锁并占满任务配额

agent/database.py:1487 resume_task · agent/jobs.py request_cancel
暂停中的任务收到取消请求后：无 worker 处理取消（任务已暂停挂起），而 resume_task 的 SQL 带 AND cancel_requested=0 条件拒绝恢复。任务永久卡在 paused，持续占用“活动任务上限 6”配额，导致后续新任务全部被 429 拒绝（实测复现：6 个 paused 任务 → ask 全部 429，UI 仅显示“请求失败”）。临时库中已手工终态化该任务以继续测试。

观察 #3（P3 · UX）：“查看改动”恒为空

DiffActivity 两处入口（ProjectDetailActivity/ConversationActivity）均不传 turn_id，服务端退回 git_diff()；模板工作区非 git 仓库 → 恒返回“无文本 diff”。建议默认按最近 turn 的 checkpoint diff 展示。

观察 #4（P3 · UX）：Checkpoint 恢复冲突提示笼统

带第三方漂移执行整体恢复时服务端返回 409 + 冲突文件列表（preview API 数据正确），客户端仅显示“请求失败”，未展示冲突文件与 expected/current 哈希，用户无法自助决策。

观察 #5（P3 · UX）：设备被撤销后 App 不跳登录页

设备会话被撤销后，App 内所有 API 请求 401，但界面停留在空白列表/错误提示，无强制登出引导，需用户手动退出重登。建议监听 401 触发踢出流程。
